# QA Forge

A Claude **skill** and **plugin** that gives QA teams one consistent, tool-agnostic workflow:

**requirements → risk → test design → plan → traceability → execution/automation → defects → reporting**

- **Requirements from anywhere** — BRDs, PRDs, SRS docs, Jira (Cloud and Server/DC), Azure DevOps (Services and Server), Confluence/wiki.
- **Automation through MCP servers, not just one** — Playwright, Selenium, Appium, Chrome DevTools, BrowserStack, Postman, plus tracker servers (Atlassian Rovo, Azure DevOps, GitHub).
- **Guided authentication** — OAuth 2.1, API tokens, PATs, Azure CLI, Entra ID; least-privilege scopes; secrets only ever as `${VAR}`.
- **Works without integrations too** — every phase degrades to CSV/JSON import files or a manual checklist.
- **Traceability built in** — every test case maps to a requirement, every defect to a test case; RTM and go/no-go report generated by scripts.

## Install

### As a Claude Code plugin (recommended)

```bash
/plugin marketplace add kaushalyacode/QA-Forge
/plugin install qa-forge@qa-forge
```

Then run `/qa-forge:setup` in your project. Commands, agents and MCP servers are listed in [plugins/qa-forge/README.md](plugins/qa-forge/README.md).

### As a standalone skill

- **Claude Code:** copy `plugins/qa-forge/skills/qa-forge` to `~/.claude/skills/qa-forge` (personal) or `.claude/skills/qa-forge` (project).
- **Claude apps (claude.ai / desktop):** zip the `plugins/qa-forge/skills/qa-forge` folder and upload it under Settings → Capabilities → Skills. The CI workflow also publishes `qa-forge-skill.zip` as a build artifact.

## How it works

| Phase | You get | Command |
|---|---|---|
| 0 Connect & authenticate | Integration status table, `qa/qa-forge.config.json` | `/qa-forge:setup` |
| 1 Requirements intake | `qa/requirements/requirements.json`, ambiguity log | `/qa-forge:intake` |
| 2–3 Risk & test design | `qa/test-cases/test-cases.json`, RTM | `/qa-forge:design` |
| 4 Test plan | `qa/plans/<release>-test-plan.md` | `/qa-forge:plan` |
| 6 Automation & execution | Code, `results.json`, JUnit, evidence | `/qa-forge:automate`, `/qa-forge:execute` |
| 7 Defects | Bug drafts → Jira / ADO after approval | `/qa-forge:bug` |
| 8 Reporting | Summary report + GO / NO-GO draft | `/qa-forge:report` |
| Export | ADO Test Plans / Xray / Zephyr CSV, Gherkin | `/qa-forge:export` |

## Supported integrations

| Category | Servers / systems | Auth |
|---|---|---|
| Web automation | Playwright MCP, Selenium MCP | none / Grid URL |
| Browser diagnostics | Chrome DevTools MCP | none |
| Mobile | Appium MCP | local SDKs |
| Device cloud | BrowserStack MCP | username + access key |
| API | Postman MCP | API key |
| Jira Cloud + Confluence | Atlassian Rovo MCP | OAuth 2.1 or admin-enabled API token |
| Jira Server/DC | mcp-atlassian | PAT |
| Azure DevOps Services | `@azure-devops/mcp` (local) / remote (preview) | Browser, Azure CLI, token env var / Entra ID |
| Azure DevOps Server | mcp-server-azure-devops | PAT |
| CI / PRs | GitHub MCP | OAuth / fine-grained PAT |

Full details: [`integrations-and-auth.md`](plugins/qa-forge/skills/qa-forge/references/integrations-and-auth.md) and [`mcp-catalog.md`](plugins/qa-forge/skills/qa-forge/references/mcp-catalog.md).
